LESSON 2: COMMON MISTAKES
=========================

1. A bad fifth argument or an overwritten local.
   Before CALL, argument 5 belongs at [rsp+20h], not [rsp+28h]. The latter is
   our output local. Label which RSP each diagram uses.

2. A call fails or crashes after changing the frame size.
   Check storage and alignment separately. For this zero-PUSH frame, subtracting
   30h leaves RSP 8 modulo 16; 38h aligns it.

3. An invalid standard handle.
   STD_OUTPUT_HANDLE is the DWORD bit pattern -11, passed in ECX. It is a
   selector, not the returned handle. GetStdHandle can return
   INVALID_HANDLE_VALUE (-1 as a HANDLE) or NULL if no standard handle exists. A
   later WriteFile can fail even with a non-null handle.

4. A second write uses a bad handle or buffer address.
   RAX, RCX, RDX, and R8-R11 are volatile. Save live state outside the outgoing
   shadow space, then reload each argument before the next call.

5. An operand-size error while storing zero.
   Use "mov qword ptr [rsp+20h], 0" for the pointer-sized fifth argument. The
   immediate zero cannot tell MASM the destination's width.

6. A pointer is truncated.
   A DWORD uses 32 bits; a pointer/HANDLE uses 64. Copying a pointer through EDX
   loses its high bits. Writing a small DWORD value through R8 rather than R8D
   is not inherently a failure, but R8D expresses the API type and ensures the
   intended 32-bit operation.

7. The "length" observed in EAX is only 1.
   EAX is WriteFile's BOOL result (any nonzero value means success). Read the
   DWORD through lpNumberOfBytesWritten for the actual byte count. In this
   synchronous form, supply a valid writable DWORD and NULL for lpOverlapped.

8. The output differs after changing message.
   Count bytes, including CR and LF. EQU $ - message measures emitted bytes;
   WriteFile neither searches for a terminator nor adds a newline.
