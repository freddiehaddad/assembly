EXERCISES
=========

Tier 1: Verification
---------------------

These exercises confirm you can build and run the program.

1. Change the exit status from 42 to 0. Rebuild and verify the exit status.

2. Change the exit status to 255. What do you observe? Why?
   (Hint: consider that exit codes are typically unsigned 8-bit values on Unix,
    but can be larger on Windows.)

3. Change the exit status to 1, then to 7. Verify each builds and runs.


Tier 2: Understanding
---------------------

These exercises test deeper comprehension.

4. Before you change anything, predict what will happen:
   Replace "mov ecx, 42" with:
       xor ecx, ecx
       inc ecx
   
   Will this produce the same exit status? Verify your prediction.
   Explain why (or why not).

5. Read the Windows documentation for ExitProcess:
   https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-exitprocess
   
   What is the parameter? What type is it? Why can you pass any value?

6. Explain why the stack must be 16-byte aligned before a CALL instruction.
   (Hint: see lessons/concepts/stack-alignment.txt if unsure.)


Tier 3: Extension
-----------------

These exercises challenge you to apply the lesson to new problems.

7. Write a second procedure named "double_and_exit" that takes one argument in RCX,
   multiplies it by 2, and passes the result to ExitProcess.
   
   Call it from main with the value 21. Verify the exit status is 42.

8. Modify the program to call ExitProcess twice, with different exit codes.
   (Hint: ExitProcess does not return, so you will not reach the second call.
    This is a "gotcha" exercise; explain why.)

9. Write a procedure named "check_range" that receives one value in RCX.
   If the value is between 0 and 10 (inclusive), call ExitProcess(0).
   Otherwise, call ExitProcess(1).
   
   Test it with values 0, 5, 10, and 11 by calling it from main with each value.
