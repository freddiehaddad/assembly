RSP VIEWPOINTS: THE ADDRESS STAYS THE SAME
=======================================

An offset is measured from a particular RSP value at a particular time.
Label that moment before calculating. A callee is also a caller when it
makes a nested call.

BEFORE CALL AND AT CALLEE ENTRY
------------------------------

Suppose the caller has finished its frame setup:

    Caller RSP before CALL = 1000h
    Argument 5 is stored at [rsp+20h] = address 1020h

CALL pushes an eight-byte return address:

    Callee RSP at entry = 0FF8h
    Argument 5 is at [rsp+28h] = 0FF8h + 28h = 1020h

The parameter did not move. The reference register changed.

    Location             Caller before CALL       Callee at entry
    New return address   not pushed yet           [rsp+00h .. rsp+07h]
    Shadow space         [rsp+00h .. rsp+1Fh]      [rsp+08h .. rsp+27h]
    Argument 5           [rsp+20h .. rsp+27h]      [rsp+28h .. rsp+2Fh]
    Argument 6           [rsp+28h .. rsp+2Fh]      [rsp+30h .. rsp+37h]

For the SAME location, in these two moments only:

    callee_entry_offset = caller_offset + 8

AFTER THE CALLEE BUILDS ITS OWN FRAME
------------------------------------

The "+8" rule is not valid forever. If this callee then executes:

    push rbx       ; RSP = 0FF0h
    sub rsp, 30h   ; RSP = 0FC0h

Its incoming fifth argument is now at [rsp+60h]:

    28h entry offset + 08h PUSH + 30h allocation = 60h
    0FC0h + 60h = 1020h, still the same address

If it calls another procedure, it places THAT procedure's fifth argument
at its current [rsp+20h]. This is a different location from its own
incoming fifth argument at [rsp+60h].

General rule for an incoming location after P pushed bytes and N allocated
bytes:

    body_offset = callee_entry_offset + P + N

PASSING AN ADDRESS
------------------

In Lesson 2, with the caller's frame already allocated:

    lea r9, [rsp+28h]
    mov qword ptr [rsp+20h], 0
    call WriteFile

R9 receives an actual address, not the number 28h. WriteFile uses that
address to write a DWORD. Moving RSP during CALL does not adjust the
pointer in R9, and no adjustment is needed: the local remains at the same
memory address.

The local at [caller rsp+28h] and the fifth argument at [callee entry
rsp+28h] are NOT the same object. Their equal-looking offsets use different
base addresses.

CHECKPOINT
----------

With caller RSP = 1000h, name the absolute address of its bytes-written
local at [rsp+28h]. What offset names that local at callee entry? What
offset names it after the callee's PUSH RBX and SUB RSP,30h above?

Check by adding each offset to its corresponding RSP, not by memorizing
which occurrence of 28h "looks right."
